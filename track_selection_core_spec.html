Track Selection Sets

Core specification for multi-track selection in MOQ Transport. Defines Selection Sets, two built-in selection policies (Top-N and Bandwidth-Aware), and the Hard switching mechanism — everything needed for conferencing in one spec.

Core Spec Top-N SSTS/BW-Aware Hard Switch Conferencing Extensible

Introduction

A subscriber often needs a relay to forward only a subset of tracks from a namespace. Two scenarios drive the design:

Figure 1: The two scenarios that drive the design — both in core.

This specification defines three capabilities to address both scenarios:

CapabilityWhat It IsCore Status
Selection Set MembershipHow tracks are grouped as candidatesCore — two modes (namespace + per-track)
Selection PolicyAlgorithm that picks the selected subsetCore — Top-N (0x0) and BW-Aware (0x1)
Switching MechanismHow transitions are executedCore — Hard (0x0). Aligned (0x1) in extension.

Why Both Policies in Core?

Top-N and BW-Aware represent the two fundamental membership modes — namespace-scoped and per-track. Including one of each in the core spec means: (1) both membership paths are fully specified, (2) the composition story is complete in one document, (3) implementers get a working conferencing system from the base spec.

Selection Sets

A Selection Set is a group of tracks from which a publisher (or relay) forwards a selected subset. Tracks outside the selected subset are not forwarded.

Figure 2: Implicit sets span a namespace; explicit sets are per-track.

Wire Formats

TRACK_SELECTION {              // Implicit membership
  Type (vi64) = 0x29,
  Length (vi64),               // 0 = remove filter (all tracks pass)
  Policy ID (vi64),
  Switch Mode (vi64),
  [Policy-specific fields]
}
Appears in: SUBSCRIBE_TRACKS, REQUEST_UPDATE

SELECTION_SET_ASSIGNMENT {     // Explicit membership
  Type (vi64) = 0x41,
  Length (vi64),               // 0 = remove from set
  Set ID (vi64),
  Policy ID (vi64),
  [Policy-specific fields]
}
Appears in: PUBLISH_OK, REQUEST_UPDATE

A track MUST be in at most one selection set. Assigning a track to a second set: REQUEST_ERROR. When a set has no remaining members, it is deleted.

Track State Machine

Deselected list: Publishers SHOULD retain recently deselected tracks for efficient reselection (NOTIFY FWD=1 vs new PUBLISH). MAY send PUBLISH_DONE to purge old entries and bound memory.

Policy 0x0: Top-N Selection

Core Policy — Namespace-Scoped

Selects the MaxTracks tracks with the highest values for a specified property. Canonical use case: active speaker detection.

TRACK_SELECTION with Policy 0x0 {
  Type (vi64) = 0x29,
  Length (vi64),
  Policy ID (vi64) = 0x0,
  Switch Mode (vi64),
  Property Type (vi64),     // MUST be even (single integer value)
  MaxTracks (vi64),         // MUST NOT be 0, <= MAX_SELECTED_TRACKS
}

Selection Rules

  1. A track is selected if it has one of the MaxTracks highest values for Property Type among all tracks in the namespace.
  2. Tie-breaking: earlier-delivered qualifying object wins. Selected tracks stay selected until a strictly higher value pushes them out.
  3. SELECTION_TIMEOUT (Track Property 0x32, default 1000ms): deselect after timeout elapses without a new qualifying object.
  4. Out-of-order: Objects with location < largest received for that track are ignored for evaluation (but pass if already selected).
  5. On REQUEST_UPDATE: re-evaluate with new params; signal all changes.

Individual SUBSCRIBE Interaction

A track individually subscribed via SUBSCRIBE in the same namespace is independent — not modified by Top-N, not counted against MaxTracks. Subscriber receives up to MaxTracks + individually subscribed tracks.

Relay Aggregation

Same Property Type, same namespace: upstream uses max(MaxTracks) across subscribers; evaluate per-subscriber locally. For audio_level: relays SHOULD precompute top-N ordering as objects arrive.

Policy 0x1: Bandwidth-Aware Selection

Core Policy — Per-Track (Explicit Membership)

Selects the highest-quality track per selection set that fits available bandwidth. Designed for sets of quality renditions (720p, 1080p, 4K).

SELECTION_SET_ASSIGNMENT with Policy 0x1 {
  Type (vi64) = 0x41,
  Length (vi64),
  Set ID (vi64),
  Policy ID (vi64) = 0x1,
  Throughput Threshold (vi64),   // min kbps to select this track
  Set Weight (vi64),             // 1-10, proportional allocation
  Activate Switching (vi64),     // start after N tracks in set
  Set Rank (8),                  // lower = higher priority
}

Bandwidth Allocation Algorithm

B_remaining = B_total

for each distinct rank r, ascending:
  active = { sets with rank == r, enough members to activate }
  sum_w  = sum(set.weight for set in active)

  repeat:
    for each set in active:
      set.target   = B_remaining * set.weight / sum_w
      set.selected = highest-threshold track where threshold <= set.target
    remove saturated sets (selected == max-threshold track), reallocate
  until stable

  B_remaining -= sum(selected thresholds at this rank)

Result: exactly 1 track per active set → Forward=1
        all others → Forward=0

Strict priority: lower-rank sets receive full allocation before higher-rank sets get anything. Weight only mediates within same rank.

Upstream: Publisher SHOULD keep Forward=1 upstream for ALL tracks in a set, regardless of downstream forwarding, to enable immediate quality switching.

Set Lifecycle

  • Created when first SELECTION_SET_ASSIGNMENT with a Set ID is received.
  • Activates once assigned track count >= Activate Switching.
  • Deleted when all members are removed (UNSUBSCRIBE, PUBLISH_DONE, reassign).
  • Set-level properties (Weight, Rank) updated by latest SELECTION_SET_ASSIGNMENT.

Hard Switch (Mode 0x0)

Core Switch Mode — Mandatory to Implement

Immediate switching. Simple, always correct. May produce a brief gap. Seamless transitions require the Aligned mode extension.

On deselection (SELECTED -> DESELECTED):

  1. Immediately stop forwarding objects for the track.
  2. Reset outstanding streams for the track.
  3. Objects in flight may still arrive.
  4. Send PUBLISH_STATE_NOTIFY with Forward=0.

On selection (-> SELECTED):

  1. Begin forwarding from joining location.
  2. Send PUBLISH (new) or PUBLISH_STATE_NOTIFY Forward=1 (reselect).

Setup Negotiation

MAX_SELECTED_TRACKS (Setup Option 0x09)
  Value: varint. Default: 0 (selection sets not supported).
  Limits total concurrently selected tracks across all sets.
  Exceed → PROTOCOL_VIOLATION.

SELECTION_POLICIES (Setup Option 0x0A)
  Value: Count (vi64), then Count × Policy ID (vi64).
  Default: empty (not supported).
  Sending a policy not in peer's list → PROTOCOL_VIOLATION.

Selection sets are usable when both MAX_SELECTED_TRACKS > 0
and SELECTION_POLICIES is non-empty.

Relay Behavior

Figure 4: Relay pipeline — same structure for all policies.

Key Rules

  • Namespace-scoped (Top-N): Relay MUST subscribe to all tracks upstream to evaluate the policy. Aggregate using max(N) when possible.
  • Per-track (BW-Aware): Relay SHOULD keep Forward=1 upstream for all set members to enable fast quality switching.
  • Precomputation: For audio_level, relay SHOULD precompute top-N continuously. New subscribers are served from cached state.
  • Aggregation: Same-policy, same-property, same-namespace subscribers share one upstream subscription. Different policies or properties: separate evaluations, or unfiltered upstream + local evaluation.

Client Behavior

Subscriber

  1. SETUP: Send MAX_SELECTED_TRACKS and SELECTION_POLICIES.
  2. Speaker selection: SUBSCRIBE_TRACKS with TRACK_SELECTION (Policy=0x0).
  3. Quality selection: On receiving PUBLISH, respond with PUBLISH_OK + SELECTION_SET_ASSIGNMENT (Policy=0x1) to group renditions.
  4. Handle signals: PUBLISH FWD=1 (render), NOTIFY FWD=0 (stop), NOTIFY FWD=1 (resume).
  5. Update: REQUEST_UPDATE with new params. Length=0 to remove.

Publisher / Relay-as-Publisher

  1. Validate Policy ID and MaxTracks on SUBSCRIBE_TRACKS.
  2. Evaluate policy. Send PUBLISH for initially selected tracks.
  3. Re-evaluate continuously as objects arrive.
  4. On change: Apply switch mode, send PUBLISH/NOTIFY/DONE.
  5. Manage deselected list. Purge via PUBLISH_DONE.

Two-Layer Composition

Having both Top-N and BW-Aware in core enables the complete conferencing pattern in a single spec:

Figure 5: Layer 1 picks participants (Top-N). Layer 2 picks quality (BW-Aware).

Independence

Speaker changes (Layer 1) don't affect quality selection for unchanged speakers. Bandwidth changes (Layer 2) don't affect speaker selection. Same state machine, same signaling, same or different switch modes.

Extension Points

The framework is extensible at three points via IANA registries:

New Selection Policies

Policy IDNameDescription
0x2ThresholdSelect all tracks above a property value threshold
0x3Bottom-NSelect N tracks with LOWEST property values
0x4Conditional AssignmentAuto-assign tracks to per-participant sets based on conditions (bridges Top-N and BW-Aware automatically)

Each new policy: defines policy-specific fields after Policy ID, specifies selection rules and aggregation, uses existing state machine and signaling.

New Switch Modes

ModeNameDescription
0x1AlignedDrain to group boundary before deselecting (seamless)
0x2CrossfadeOverlap old and new track for blended transition

New modes define deselection timing; use existing state machine and signaling. The Aligned mode (PR #1675, renamed from "Soft" per Gwendal's suggestion) is the first expected extension.

Conditional Set Assignment (Future)

Today, the subscriber must manually assign each PUBLISH'd track to a selection set via PUBLISH_OK. A future Conditional Assignment policy would automate this: "When a track is selected by Top-N, auto-assign its rendition tracks to a per-participant BW-Aware set with these defaults." This would collapse the two-step conferencing flow into a single SUBSCRIBE_TRACKS.
